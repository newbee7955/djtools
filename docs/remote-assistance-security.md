# 豆角桌面端远程协助安全架构与设计规范 (Remote Assistance Security Architecture)

## 1. 概述与核心安全原则

豆角（Doujiao）远程协助功能旨在为公网环境下的用户提供轻量、安全、低延迟的双向远程桌面协助支持。系统架构设计遵循以下核心安全原则：

1. **绝对有人值守（Strictly Attended Access Only）**：
   - 绝不允许任何形式的“无人值守”（Unattended Access）后台控制或自启动静默连入。
   - 每次被协助连接必须由被控端用户在前台手动点击确认授权。
   - 授权范围精确分为「仅观看屏幕（View-Only）」与「允许键鼠控制（Control）」两种模式，默认推荐仅观看。

2. **客户端零入站监听端口（Zero Inbound Ports）**：
   - 客户端机器绝不在本地开放任何 TCP/UDP 监听端口，彻底规避 Windows 防火墙弹窗及内网端口扫描风险。
   - 客户端与公网信令服务器之间通过安全的出站双向 WebSocket（WSS:443）保持连接。

3. **控制权被控端最高优先级（Host Preemption & Killswitch）**：
   - 本地物理外设具有最高抢占权：被控端只要移动本地鼠标或敲击键盘，远端控制将立即被硬件级熔断暂停 1500 毫秒（Local Override）。
   - 提供多重即时中断机制：屏幕顶部常驻悬浮断开栏、系统托盘右键断开菜单，以及系统级全局紧急热键（`Ctrl+Alt+Shift+Esc`）。

## 2. 身份凭据与设备寻址安全

### 2.1 密钥生成与 DPAPI 保护
- 客户端在首次启动时，通过 Node.js 原生 `node:crypto` 生成专用的 Ed25519 密钥对（`crypto.generateKeyPairSync('ed25519')`）。
- 私钥持久化存储采用 Electron 的 `safeStorage` API，在 Windows 系统下直接通过 Windows 数据保护接口（DPAPI，CryptProtectData）结合当前登录用户凭据进行硬件级加密存储，无法被跨用户或离线文件拷贝读取。
- 身份文件写入采用「临时文件 + 重命名」的原子写，避免写入中断导致身份损坏。存储中记录 `privateKeyProtected` 标记以区分加密/降级明文存储；当 `safeStorage` 不可用且私钥曾被加密时，不会误读为明文，而是报告解密失败后重新生成身份（设备码随之变化）。

### 2.2 9 位设备识别码派生
- 设备码由公钥（SPKI DER）的 SHA-256 哈希确定性派生：取哈希 hex 前 12 个字符转为大整数，对 `900000000` 取模后加 `100000000`，得到 9 位数字（不含 Luhn 校验位）。
- 格式化为 `XXX XXX XXX`（如 `839 201 442`），便于用户口头交流或文字复制。

### 2.3 6 位固定安全码（连接口令）
- 每台设备在本机生成一串 6 位随机安全码并**持久化存盘**（可手动刷新更换），展示在远程协助插件页。
- 控制端发起协助时**输入**该安全码；被控端在确认授权弹窗中即时比对（`safetyCodeMatched`）：不一致时「允许协助 / 仅允许查看」按钮被禁用，并给出醒目警示。
- 作用定位：它相当于一把**连接口令**——只有拿到你口令的人才能发起一次被接受的协助请求。注意其局限：仅 6 位、跨会话复用、且随会话请求经信令服务器明文转发，因此**不构成端到端机密**，安全强度有限。
- 真正的访问控制仍是"被控端每次前台手动同意"（见 §1）；安全码只是额外的便捷校验层。
- 已知局限：当前不校验 WebRTC 的 DTLS 指纹/公钥，因此无法发现"纯转发 + 替换媒体密钥"型的中间人；若要达到该强度，需把 SDP 指纹（或双方公钥）纳入核对材料。

## 3. 输入控制安全隔离与 Win32 原生辅助进程

### 3.1 独立辅助进程隔离 (`doujiao-remote-input.exe`)
- Electron 主进程不直接调用 Win32 API 模拟键盘鼠标，而是由受限的独立 C++ 辅助进程执行。
- 辅助进程与主进程之间仅通过**匿名继承标准输入管道（Inherited Stdin Pipe）**通信，不对系统开放任何本地网络或具名管道端点。

### 3.2 256 位会话 Token 校验
- 辅助进程启动后，主进程首先通过 stdin 发送由 CSPRNG 生成的 256 位随机十六进制 Session Token。
- 辅助进程只有在校验握手帧的 Token 完全匹配后才会进入就绪状态；若收到未授权输入或管道异常，进程立即退出并释放全部按键。

### 3.3 输入坐标归一化与边界截断
- 控制端只传输归一化坐标 `(x, y) ∈ [0.0, 1.0]`，主进程严格进行浮点校验与 `clamp(0.0, 1.0)` 限制，拒绝任何 `NaN`、无穷大或超出屏幕范围的异常指令。
- 单包大小上限为 4096 字节（`MAX_INPUT_PAYLOAD_BYTES`）防止畸形大包；主进程额外对远程输入做每秒 200 事件（`MAX_INPUT_EVENTS_PER_SECOND`）的限流，超出部分直接丢弃，防止异常或恶意客户端发起洪泛攻击。

### 3.4 退出与异常按键安全释放 (`release-all`)
- 无论是会话主动挂断、网络超时、窗口关闭、紧急快捷键触发还是辅助进程崩溃，辅助进程在退出前均会无条件调用 `SendInput` 释放所有键盘修饰键（Ctrl/Alt/Shift/Win 等）及鼠标按键，确保用户物理机不会残留“按键粘连”状态。

## 4. 实时监控与多重熔断防御机制

| 熔断通道 | 触发方式 | 生效时延 | 行为表现 |
| :--- | :--- | :--- | :--- |
| **本地鼠标抢占 (Local Override)** | 被控端晃动本地鼠标 / 击键 | 实时 (硬件级事件检测) | 立即暂停远程输入 1.5 秒，显示黄色警告提示 |
| **顶部常驻胶囊悬浮条** | 点击悬浮条上的「立即断开」按钮 | < 50ms | 销毁 WebRTC 会话、关闭辅助进程、恢复正常桌面 |
| **系统托盘菜单** | 右键托盘图标 -> 「断开当前远程协助」 | < 50ms | 全局广播断开指令并重置为待命状态 |
| **全局紧急热键** | 按下 `Ctrl + Alt + Shift + Esc` | < 10ms (OS 级热键) | 强行终止远端控制及媒体捕获流 |
| **心跳超时熔断** | 信令服务端持续无响应超过存活超时（默认心跳间隔 25s × 3 = 75s） | 自动检测 | 客户端心跳看门狗强制断开并触发重连，切换至断开状态，释放全部资源 |
| **握手超时熔断** | 进入 `connecting` 后 30s 内未建立 WebRTC 连接 | 30s | 主动断开并回报 `handshake-timeout`，避免因 offer/answer/ICE 丢包或屏幕捕获挂起导致永久卡在"握手中" |

> 说明：本地鼠标抢占的暂停由原生辅助进程硬件级实现（1.5 秒），宿主会将该事件（`local-override`）转发到插件界面显示黄色提示条。

## 5. WebRTC 音视频与信令传输安全

1. **端到端加密**：
   - WebRTC 媒体流采用 SRTP (AES-128/256-GCM) 强加密，DataChannel 采用 DTLS 1.2+ 加密，第三方网络节点无法窃听画面。

2. **公网信令转发最小化**：
   - 信令服务器（`remote-assist-signal`）仅负责分发设备在线状态与对等握手 SDP/Candidate 报文，完全不解析、不存储任何桌面画面或操作输入。

3. **设备身份认证与来源绑定**：
   - 客户端 `register` 报文包含 Ed25519 签名（签名内容为 `deviceCode:timestamp`）与 SPKI 公钥；信令服务器强制校验签名有效性、时间戳新鲜度，并要求「公钥派生的设备码 == 声明设备码」，否则回 `REGISTER_REJECTED` 并断开。
   - 注册成功后，服务器把设备码与该连接绑定；此后所有报文必须 `from` 与绑定身份一致，否则回 `IDENTITY_MISMATCH` 并丢弃，杜绝设备码冒充。
   - 客户端侧进一步校验会话内信令（`offer`/`answer`/`ice-candidate`/`disconnect`/`session-response`）来源必须等于当前对端设备码且 sessionId 一致。

4. **动态短效 TURN 凭据**：
   - 基于时间戳与 HMAC-SHA1 机制，信令服务器向合法客户端分发有效期仅 5 分钟的临时 TURN 凭据，杜绝未授权流量盗用。
   - 客户端在凭据临近过期（剩余 ≤ 60s）时自动重新注册以续期。

5. **信令连接加固**：
   - 服务端仅接受 `Sec-WebSocket-Version: 13`，客户端帧必须携带掩码；支持分片重组，单帧/单消息上限 512KB，超出以 1009 关闭；单连接每秒消息数超过 40 丢弃；写侧带背压队列，关闭时回送关闭帧。
   - 客户端在信令断线期间会缓存会话关键信令（session-request/response、offer、answer、ice-candidate、disconnect，上限 64 条），重连注册后按序补发，避免丢包导致握手永久卡住；主动断开时清空缓存。
   - 受控端屏幕捕获带单次 8s 超时与最多 2 次重试，失败或超时会以 `screen-capture-failed` 明确退出，不再无限等待而卡住握手。

6. **直连优先与受控中继回退**：
   - 每次会话的第 0 代 ICE 只启用 host/STUN 候选，避免响应更快的 TURN 候选先被提名后锁定整代连接。
   - 仅控制端（ICE controlling peer）负责回退决策；计时从 `iceConnectionState=checking` 开始，而不是从窗口创建或屏幕捕获开始。直连 5 秒仍未建立时，控制端加入 TURN 配置并发起一次 ICE restart，受控端依据 `iceGeneration` 与 `icePhase` 同步切换。
   - offer、answer、candidate 与 end-of-candidates 都携带 ICE 代次；旧代候选直接丢弃，超前代候选等待对应 SDP，避免重启前后的候选交叉污染。
   - 路径类型以 WebRTC `transport.selectedCandidatePairId` 指向的候选对为准；连接刚建立但尚未识别候选对时只显示“正在识别链路”，不会提前宣称 P2P。
   - 排障时可在启动宿主前设置 `DOUJIAO_REMOTE_ICE_MODE=direct-only`。该模式从 `checking` 起保留 10 秒纯 host/STUN 观测窗口、打印完整 ICE 诊断且绝不启用 TURN。Windows PowerShell 示例：`$env:DOUJIAO_REMOTE_ICE_MODE='direct-only'; npm run dev`。
   - STUN Binding 探测只说明 TURN UDP 端点响应；TURN Allocate、临时凭据鉴权与中继端口是否真正可用，最终仍以 ICE 结果为准。UDP 探测失败只剔除 UDP TURN URL，不会误删显式 TCP/TLS 中继回退。

7. **传输与剪贴板（V2）**：
   - 文件/图片/剪贴板内容走独立的 `doujiao-data` 有序通道，全程 P2P（DTLS/SCTP）加密，不经信令服务器。
   - 入站文件授权为**会话级**，可在**插件页**随时撤销；撤销后所有入站 `transfer-offer` 一律拒绝。
   - 受控端对接收路径做强制校验（拒绝 `..`、绝对路径、盘符、保留设备名），并对单文件大小与磁盘空间做预检。
   - 剪贴板同步默认开启（文本/图片/文件三类各自可关），并有可见指示；剪贴板内容可能包含敏感信息，用户可随时关闭。
   - 剪贴板文件采用"暂存 + `FileNameW` 置入系统剪贴板"的方式，落点由用户在接收端粘贴时决定；会话结束清理暂存。
